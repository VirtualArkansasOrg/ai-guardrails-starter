# A one-paragraph policy

A starting point. Change it to fit, and have your attorney check it against FERPA, state student privacy law and your board policy.

> Staff may use district-approved AI tools to build software for district work. Any tool that uses district credentials, touches student or staff data, or is used by anyone besides the person who built it lives in the district's GitHub organization, is reviewed by a named technical owner before anyone else uses it, and is listed in the district's tool inventory. Passwords, keys and tokens are never written into code or pasted into an AI tool. Student data goes only into AI accounts the district manages. Staff who built tools before this policy can bring them in without penalty, and the technology department will help.

## Why each part is there

- **"Uses district credentials, touches student or staff data, or is used by anyone besides the person who built it."** This is the scope. A teacher's personal flashcard script is out; a grade export is in.
- **"Lives in the district's GitHub organization."** If it's in the org, IT can see it, and it survives the builder leaving.
- **"Reviewed by a named technical owner."** A second person signs off. Name the person or team, not a department.
- **"Listed in the district's tool inventory."** Covers tools that never touch Git (Apps Script, Power Automate, browser extensions, custom GPTs). See [tool-inventory.csv](tool-inventory.csv).
- **"Never pasted into an AI tool."** Pasting a key or a student list into an AI chat sends it to the AI provider.
- **"Without penalty."** Without this line, staff stop telling you what they've built, and the tools stay invisible.
